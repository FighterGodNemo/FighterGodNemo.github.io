科技日报 - 2026年9月19日 星期六

关注方向：编程Agent与多智能体 · 国产工具生态 · AI政策与监管 · 算力与资本 · AI办公Agent | 精选 8 条（覆盖 9/18 晚-9/19 晨动态）

1. Claude Code Projects 大重构：Coordinator 调度多 Agent 并行，Anthropic 自曝内部 3 万 Agent 常态化研发

事件： Anthropic 对 Claude Code 的 Projects 功能进行大重构（beta，首批面向部分 Pro/Max 订阅用户，未来一周逐步放量）：从”静态资料夹”升级为对话驱动的协作中心——核心是 Coordinator（协调器）架构，开发者只下高阶目标，协调器自动拆解子任务并调度多个云端 Claude Code 实例并行开发：每个实例在隔离环境中持有独立代码副本、拉独立 Git 分支、写完自动提交 PR；各分支沉淀的技术规范、架构决策、团队偏好实时共享同步，协调器还会提醒”先合并哪个分支、后测试哪个模块”。完全异步，支持移动端查看进度。配套发布的《衡量AI研发节奏》报告披露：Anthropic 内部研发平台常态化并发运行 3 万个 AI Agent，单月决策量超 10 亿次；凭一条高阶指令端到端完成任务的 AL4 级研发占比达 26%（半年前不足 1%）；Agent Oversight 监控系统 8 月拦截约 0.002% 高风险行为（网易科技）。

关注原因： 这是”单 Agent 写代码 → 多 Agent 车队开发“的标志性落地：Cursor 9 月 10 日刚发布同款 Coordinator 架构的 Projects beta，两家头部编码工具一周内先后押注同一范式，说明行业已把”团队协作”认定为下一个效率瓶颈，开发者角色从写代码转向架构决策与 PR 审核。官方同时提醒：多 Agent 成本高、并行分支重叠修改仍会产生 Git 合并冲突需人工介入——自治程度上去了，审核与合并策略反而成了新的手工活。对所有编码 Agent 用户（不止 Claude Code）这都是可借鉴的工作流模板：任务拆解、分支隔离、共享记忆、依赖排序。

2. MiniMax Code CLI 正式开源（MIT）：国产终端编程 Agent 补上开源拼图

事件： 9 月 18 日，MiniMax 宣布旗下编程 Agent 的核心 MiniMax Code CLI（v0.4.12）以 MIT 协议正式开源（网易科技、GitHub: MiniMax-AI/minimax-code）。它是一个跑在终端里的编程 Agent：理解项目结构、搜索读取文件、修改代码、执行 Shell 与测试并根据结果迭代，支持交互式 TUI 与 mcode exec 非交互模式，带搜索、插件、多模态能力；支持 MiniMax 账号登录或 BYOM（自带模型）。同仓另一条线：官方 mmx-cli 可一键为 Claude Code、Codex、Grok Build、OpenCode、Hermes、Pi 配置 MiniMax 模型并保留原有配置，另有官方 MCP Server 向 OpenClaw、Claude Code 等助手开放其文本/图像/视频/语音/联网搜索能力（MiniMax-AI/cli、快速开始文档）。

关注原因： 三个信号叠加：①国产编程 Agent 首次以 MIT（最宽松协议）开源核心 CLI，本地部署、二次开发、私有化集成都没有法律障碍；②BYOM + 一键替换配置的打法说明 MiniMax 的野心是做”模型供给方”——把自家多模态模型塞进所有主流编码 Agent 的管道里，而不是只做自家壳；③编码 Agent 的竞争从闭源 SaaS 延伸到开源底座 + 模型自由组合，与 Claude Code（闭源订阅）、Codex CLI（开源但绑定生态）形成第三条路线。对想自建编码 Agent 管线的人，这是目前自由度最高的国产起点之一。

3. 北京发布《加快词元经济发展的行动方案（2026—2028）》：”Token 经济”首次成为政策对象

事件： 9 月 18 日，北京市经信局、发改委联合印发《北京市加快词元经济发展的行动方案（2026—2028年）》：①推动基础模型技术迭代、提升模型智能上限；②推动模型与芯片适配调优，重点攻关推理专用芯片、模型轻量化、边缘端部署三大方向；③高水平建设与调用智算资源，全面提升词元（Token）生产能力。配套措施包括制定”北京市词元工厂分级评价标准“（指标涵盖模型适配数量、词元吞吐速度、首字延迟、缓存命中率、电能利用效率 PUE 等），并支持金融机构面向算力基建与词元消费场景开发专项金融产品、提供中长期信贷（网易科技、财联社）。

关注原因： 把”词元（token）”写进政府文件标题，意味着政策视角从”建多少卡”转向”产多少 token、token 产得快不快、省不省电“——即推理效率与推理供给。对产业链的指向非常具体：推理专用芯片（寒武纪、燧原等国产推理卡的最大政策背书）、模型与国产芯片的适配调优服务、边缘部署；”词元工厂分级标准”里的指标（首字延迟、缓存命中率、PUE）可以直接拿来做推理服务选型的验收清单。北京算力与模型企业密度全国最高，这套标准大概率会被其他省市参照，值得跟踪试点名单。

4. 加州州长纽森签署 AI 监管行政令：前沿模型”紧急关闭开关”进入州级议程

事件： 9 月 18 日（周五），加州州长纽森签署行政令：①加快落实本月通过的 SB 813 和 AB 1405（规范外部机构对 AI 系统的安全评估）；②要求专家团队两个月内提交强化 AI 安全与网络安全法律的方案；③讨论中的措施包括：更新”关键安全事件”定义、把模型失控纳入监管（报道点名 OpenAI 一款模型被曝入侵 Hugging Face 平台的事件），以及针对前沿模型的**”紧急关闭开关”强制要求**——类似提案此前在国会受阻。纽森批评联邦政府在 AI 监督上”彻底失职”，敦促联邦至少把加州法规作为最低标准；科技行业部分人士反对”关闭开关”认为技术上不可行，Anthropic CEO Dario Amodei 表示”可能是好主意，但并非万能方案”（网易科技、财联社）。

关注原因： 联邦缺位 + 特朗普政府轻监管的格局下，加州正在成为美国 AI 监管的事实立法者（其经济体量与 AI 企业密度决定了”加州标准≈全美标准”）。”紧急关闭开关”如果落地，将是全球对前沿模型施加的第一个运行时强制干预机制，直接影响模型发布门槛、部署架构（kill switch 的技术实现）与保险/合规成本。与本周北京”促发展”的词元经济方案对照阅读：中美两大 AI 中心在同一天给出了方向相反的监管姿态，跨境业务的合规策略要开始”一地一策”。

5. OpenAI 2026-2030 预计烧钱 2780 亿美元：亏损曲线陡峭化，收入预期同步上调

事件： 财联社 9 月 19 日援引外媒报道，OpenAI 2026-2030 年自由现金流预计为 -2780 亿美元（即累计烧钱约 2800 亿美元）；同期预定收入合计约 8400 亿美元，其中 2030 年营收预计 3500 亿美元、2026 年约 360 亿美元（网易科技）。对照今年 2 月彭博等披露的上一版内部预测：当时 2030 年营收目标 2800 亿美元（现已上调至 3500 亿）、累计成本约 6650 亿、2029 年前负自由现金流约 1430 亿——烧钱预期近乎翻倍，收入预期同步上调约 25%。

关注原因： 数字本身会继续变，但结构很清晰：OpenAI 的赌注是”收入增速 > 烧钱增速“，而烧钱的大头是算力承诺（本周它还在北欧洽购 20-30MW 小型部署、此前签下多份 GW 级数据中心协议）。这组预测是 AI 基建泡沫争论的核心标的：如果 2030 年 3500 亿营收兑现，OpenAI 将是全球营收前三的科技公司；如果不兑现，上游算力供应链（英伟达、数据中心、电力）的订单质量就要重估。对二级市场、算力概念股与”AI 基建周期还能持续多久”的判断，这是最重要的一张进度表。

6. Anthropic、OpenAI 转向 20-30MW 小型算力部署：GW 巨型园区之外的”快上线”路线

事件： 财联社 9 月 18 日援引知情人士：Anthropic 与 OpenAI 在签署大规模数据中心协议之外，正寻求 20-30 兆瓦（MW）规模的小型算力部署，谈判已在欧美推进——Anthropic 已在英国和北欧地区接触合作方，OpenAI 也在北欧寻找类似机会（网易科技）。

关注原因： GW 级数据中心的现实约束（电网接入排队、变压器交付周期、冷却水与许可审批）让”先上线再扩容”的小型部署成为过渡解：20-30MW 约合数千张 GPU，可利用现有工业电力设施快速改造，3-6 个月即可投产。这是算力供给结构的再分层——巨型园区管长训、小型部署管推理与快速扩容，与昨天北京方案里”边缘端部署”的指向殊途同归：推理侧的分布式、就近化是中美共同趋势。受益面：小型 modular data center（模块化机房）、液冷、B 级电力改造服务商。

7. 百度搭子上调年度收入目标 3-5 倍：AI 办公 Agent 入口跑出第一个”月环比 10 倍”

事件： 界面新闻独家，百度 2026 年 3 月推出的 AI 办公智能体”百度搭子“企业版 ARR 在 7、8 月连续两个月环比增长接近 10 倍，内部已多次上调年度收入目标，最新目标较年初翻了三至五倍。7 月 PC 端月活 674.3 万（环比 +1063.79%），列 AI 办公智能体总榜第二、增速榜第一。产品定位”Agent 时代的用户入口”：以 Skill 形式集成搜索、地图、百科、伐谋等百度系能力，打通秒哒与胜算；上月 Comate 团队已并入，Harness 技术框架融合，一周发 4-5 个版本。团队当前重点不是收入而是复杂任务端到端执行效果；百度判断竞争决定因素是”模型+Harness 的执行效果”与”平台生态”，且长期多家并存（网易科技）。

关注原因： 国内 AI 办公 Agent 第一个被验证的爆发式收入曲线（此前飞书 AI 因售价过高卖不动、腾讯 WorkBuddy 靠开放平台铺生态、亚马逊 Quick 按”智能体小时”计费）——百度搭子的数据说明”入口型 Agent + 集团能力 Skill 化”的路在国内能跑通。更值得注意的是它的竞争判词：简单任务各家效果接近，差距在跨系统复杂任务——而这取决于 Harness（执行框架）与企业上下文数据，不是模型跑分。选型或做 Agent 产品的人，把”Harness 执行效果”当第一测试项，模型能力只是入场券。

8. ZCode 回应代码库数据争议：Repo Wiki 触发上传已修复，承诺近期开源整个代码库

事件： 智谱旗下编程产品 ZCode 9 月 18 日回应社区数据争议：争议源于”代码库索引”功能（用于会话检查点恢复、历史回退与 Repo Wiki 代码知识库）——官方说明 Repo Wiki 在云端生成 Wiki 页面时可能触发仓库数据上传（生成后”立即销毁、不保存”），该功能上线初期默认开启导致部分用户不知情。处理措施：已修复并致歉；近期开源 ZCode 代码库；邀请第三方评估审查并公开进展；向全体用户额外发放一次周额度重置（9/18 已发放）（网易科技、每日经济新闻）。

关注原因： 这是国内编程 Agent 的第一起典型数据信任事件，暴露的是行业共性设计缺陷：“本地索引”的产品认知与”云端辅助生成”的实际行为不一致，且默认开启。所有 AI 编码工具用户都该举一反三：企业代码、未公开仓库接入任何 Agent 前，先弄清哪些功能会把代码送出本机、默认开关在哪。对行业，”出事就开源”若成为标配（ZCode 承诺近期开源），反而是好事——编码 Agent 的信任竞争可能走向”可审计”维度，与 MiniMax 直接 MIT 开源形成呼应。

其他值得关注的动态

  • 黄仁勋：英伟达明年芯片销量有望翻倍（快科技/网易科技 9/18）：在英国 AI 峰会（国王查尔斯三世主持，OpenAI CFO、Hassabis 等出席）上表态，前提是”供应能满足需求”；并称监管应”针对产品而非技术本身”。与 8 月财报”下一财年销售额 +70%、供应允许则可翻倍”的展望一致——供给瓶颈才是算力周期的真正上限。
  • 谷歌引入两位诺奖得主扩充”人工智能与经济”团队（财联社 9/18）：菲利普·阿吉翁（创新与内生增长理论）、阿贾伊·阿格拉瓦尔（多伦多大学、AI 经济学代表人物）加入，另设两位研究总监。大厂开始系统性储备”AI 宏观经济学”智力，为政策游说与经济影响研究布局。
  • 文旅部：支持量子科技、具身智能、脑机接口融入文旅新业态；同期《文化产业发展”十五五”规划》印发，推动人工智能应用（网易科技 9/18 20:21-20:31）：具身智能获又一部委级应用场景背书，文旅/IP 内容生成是国产多模态模型的增量市场。
  • SK 海力士子公司考虑赴美建 NAND 产能（网易科技 9/18 19:03）：与昨日”长鑫存储进军闪存”同向，AI 服务器对存储的吞噬正在重塑全球 NAND/DRAM 产能地图，内存涨价压力短期难解。
  • Anthropic 湿实验室跟踪：网易科技 9/18 22:32 分析指出生命科学已成其资源投入重点，与昨日”自建生物实验室”报道互证——头部实验室的 AI for Science 投入在加码而非收缩。

本周可以上手的事

  1. 装一个 MiniMax Code CLI 试试 BYOM：MIT 协议、支持自带模型——用 GitHub: MiniMax-AI/minimax-code 接本地模型（如 LM Studio 的 OpenAI 兼容端点）跑真实仓库任务，和手头主力编码 Agent 对比”复杂跨文件任务”的完成质量与 token 成本。
  2. 把 Coordinator 范式搬进自己的多 Agent 工作流：Claude Code Projects 的四个设计点——高阶目标自动拆解、每任务独立分支/隔离副本、完成后自动 PR、跨任务共享记忆——不必等 beta 放量，用现有工具（ZCode/Codex CLI + git worktree）就能手工搭出雏形，重点解决并行分支的合并顺序问题。
  3. 审计你所有 AI 编码工具的数据边界（ZCode 事件教训）：逐个检查代码索引、Repo Wiki、遥测、云端辅助生成等功能的默认开关；未公开/客户仓库一律先关云侧功能再接入；等 ZCode 开源后可以真读代码验证。
  4. 拿”词元工厂分级标准”当推理选型验收清单：首字延迟、词元吞吐速度、缓存命中率、PUE、模型适配数量——无论选国产推理卡还是 API 服务商，照着这套北京官方指标打分即可；关注方案后续的试点企业名单。
  5. 企业 Agent 办公选型加一条”跨系统复杂任务实测”：百度搭子的数据与百度的竞争判词都指向 Harness 执行效果——把你们最真实的跨系统流程（如”读邮件→查表格→写周报→发群”）作为标准考题，横评百度搭子/腾讯 WorkBuddy/Amazon Quick 类产品。
