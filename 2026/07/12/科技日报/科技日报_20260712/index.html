科技日报 2026-07-12

科技日报 | 2026-07-12

信息截止：2026-07-12 15:01（Asia/Shanghai）
核心窗口：近 72 小时；技术背景窗口：近 14 天
证据规则：A = 官方原文已读取；B = 官方页面存在但本次正文抓取受限；C = 权威媒体交叉验证。厂商基准默认视为自报结果，不等同于独立复现。

一句话结论

AI 竞争的重心正在从“谁有一个最强模型”转向“谁能提供分层模型、长周期智能体、可审计工具链和可落地工作环境”。本周最值得立即试用的是 GPT-5.6、ChatGPT Work 与 GPT-Live；最值得布局的工程能力是模型路由、智能体审计、Prompt/Skill 版本管理，以及面向真实环境的闭环评测。

今日五大洞察

  1. 前沿模型开始产品线化，而不是单模型化。 OpenAI 用 Sol、Terra、Luna 固化能力层级，并叠加 reasoning effort、max、ultra 等计算档位。模型选择将从“模型名”升级为“任务 × 成本 × 延迟 × 风险”的路由问题。
  2. AI 工具从对话框变成任务执行环境。 ChatGPT Work 能连接应用、浏览器和本地文件，持续运行数小时，产出文档、表格、演示文稿和站点；Codex 被整合进统一桌面工作台。竞争焦点变成“完成闭环”，而不是“回答得像不像”。
  3. 交互层和推理层正在解耦。 GPT-Live 用全双工模型维持自然语音交互，把搜索、深度推理和复杂任务委派给后台前沿模型。这种“低延迟前台 + 高智能后台”架构会扩展到客服、会议、陪练和现场作业。
  4. 智能体治理已经成为基础设施。 GitHub 开放 Copilot 会话流，企业可审计 prompts、responses 和 tool calls，并接入 SIEM；浏览器工具采用隔离会话、显式共享和域名策略。没有审计、权限和回放能力的 Agent 很难进入生产环境。
  5. 开放模型的差异化转向长上下文、代码智能体和非 NVIDIA 训练栈。 Kimi K2.7 Code 强调长周期编码与 Token 效率；LongCat-2.0 以国产 AI ASIC 完成 1.6T MoE 训练并开放 MIT 权重。开放生态不再只比参数，而是在比可部署性、许可证、工具兼容和单位任务成本。

核心动态

1. OpenAI 正式发布 GPT-5.6 系列

时间： 7 月 9 日
证据： A，OpenAI 官方原文；GitHub 官方集成公告；TechCrunch 交叉验证

发生了什么

  • 系列分为 GPT-5.6 Sol、Terra、Luna：分别面向高难长周期任务、日常均衡任务和快速低成本任务。
  • API 定价为每百万 Token：Sol 输入 $5 / 输出 $30，Terra $2.50 / $15，Luna $1 / $6。
  • 已在 ChatGPT、Codex 和 OpenAI API 上线；GitHub Copilot 同步开始分阶段接入三档模型。
  • Responses API 增加可编程工具调用；多智能体能力处于测试阶段。ultra 默认协调 4 个智能体并行工作。
  • OpenAI 自报：Sol 在 BrowseComp、OSWorld 2.0、Terminal-Bench 2.1、SEC-Bench Pro 等长周期工具使用与安全任务上刷新或接近前沿成绩。

为什么重要

模型家族化意味着应用不该再把一个固定模型写死在所有路径里。高频简单任务用 Luna，常规工作流用 Terra，复杂代码库、研究或高价值任务再升级到 Sol，才可能获得更好的单位成本产出。

立即可做

  • 从真实业务中抽取 20 个任务，分别用 Luna、Terra、Sol 执行，记录成功率、人工修改分钟数、总成本和 P95 延迟。
  • 对长任务增加预算上限、超时、人工审批点和失败回退；不要只比较单轮回答质量。
  • 若使用 Prompt Cache，评估新的显式缓存断点与至少 30 分钟缓存有效期是否能降低长上下文成本。

需要保留的判断

官方基准包含模型厂商自行选择的推理档位、工具环境和成本估算。上线前应以自己的任务集复测，不应直接把榜单分数当采购结论。

2. ChatGPT Work 将“回答”升级为“交付”

时间： 7 月 9 日
证据： A，OpenAI 官方原文

发生了什么

  • ChatGPT Work 可在应用、文件、内置浏览器和桌面环境中执行多步骤任务，并持续处理项目数小时。
  • 可生成文档、表格、演示文稿和可分享的 Sites；支持一次性、定时和事件触发任务。
  • 提供 1,400 多个插件连接 Slack、Teams、Drive、SharePoint、CRM、邮件和日历等系统。
  • 新 ChatGPT 桌面应用合并 Codex；原 ChatGPT 桌面应用更名为 ChatGPT Classic，独立 Atlas 浏览器将逐步停用。
  • Web/移动端先面向 Pro、Enterprise、Edu 推出；桌面端 Chat、Work、Codex 面向包括免费套餐在内的用户开放。

为什么重要

通用 AI 助手正在成为“个人工作操作系统”。真正的护城河不是模型能写多少文字，而是能否可靠地获取上下文、执行操作、生成最终产物，并在每个关键动作上保留用户控制权。

立即可做

  • 选择一个低风险、可人工核验的周期任务试点，例如日报、会议材料更新或周报数据核对。
  • 给试点定义完成条件：输出文件、来源链接、校验规则、最大运行时长、允许访问的工具和必须审批的操作。
  • 敏感数据暂不接入；先验证任务闭环和审计记录，再扩大权限。

3. GPT-Live 推出全双工语音架构

时间： 7 月 8 日
证据： A，OpenAI 官方原文

发生了什么

  • GPT-Live 可同时听和说，不再等待用户完整结束一轮后才回应，可持续决定倾听、暂停、打断或调用工具。
  • 深度搜索和推理由后台模型处理，前台语音仍可保持对话；发布时后台使用 GPT-5.5。
  • GPT-Live-1 面向 Go、Plus、Pro，GPT-Live-1 mini 面向 Free；API 尚未正式开放，可登记通知。
  • 首发暂不支持语音与视频或屏幕共享组合。

为什么重要

“实时交互模型 + 后台任务模型”的双层架构能同时解决低延迟与高智能之间的冲突。未来语音 Agent 的关键指标会从转写准确率转向打断管理、持续上下文、后台委派和任务完成率。

立即可做

  • 用真实场景测试打断、停顿、噪声和连续追问，不只测试标准朗读。
  • 设计语音 Agent 时把“对话状态机”和“后台任务队列”分开，允许前台持续沟通并异步回传结果。

4. GitHub Copilot 加速进入“可用、可管、可审计”阶段

时间： 7 月 9 日及近期更新
证据： A，GitHub 官方 Changelog

发生了什么

  • GPT-5.6 三档模型开始进入 VS Code、Visual Studio、Copilot CLI、GitHub Cloud Agent、移动端与主流 IDE；企业策略默认关闭，需要管理员启用。
  • GitHub.com 可为陌生仓库生成用途、技术栈和贡献指南概览；没有 README 时可辅助生成。
  • 企业可通过流式端点或 REST API 获取 Copilot 会话中的 prompts、responses 和 tool calls，并接入 SIEM 或 Microsoft Purview。
  • VS Code 浏览器工具已 GA：Agent 可操作真实网页、读取控制台和截图；Agent 标签页隔离，用户标签页需显式分享，摄像头、麦克风、位置等权限不得自动批准。

为什么重要

企业采用 Agent 的阻力正在从模型能力转向治理能力。会话可见性、工具调用记录、权限边界、网络域名控制和可回放性会成为采购硬指标。

立即可做

  • 为所有生产 Agent 统一记录：模型版本、提示模板版本、工具输入输出、批准人、工件哈希、成本、耗时和最终结果。
  • 浏览器自动化默认使用隔离会话，并对外部域名设置 allowlist；涉及敏感权限时必须人工批准。

5. Mistral Studio 将 Prompt 和 Skill 视为受治理资产

时间： 约 7 月 9 日
证据： B，Mistral 官方页面已被索引；本次官方正文抓取超时

发生了什么

Mistral Studio 新增 Prompt 与 Skill 的版本控制、所有权和可追踪记录，目标是让这些资产像代码一样迭代和发布。

为什么重要

Agent 的实际行为不仅由模型决定，也由系统提示、工具说明、Skill 和运行策略共同决定。没有版本号和变更记录，就无法复现实验、解释回归或可靠回滚。

立即可做

  • 将 Prompt/Skill 纳入 Git：语义版本、变更说明、评测集、负责人、上线时间、回滚版本缺一不可。
  • 将评测结果绑定到“模型版本 + Prompt 版本 + Skill 版本 + 工具版本”的完整组合。

6. 开放编码模型继续压低 Agent 成本

时间： Kimi K2.7 Code 6 月 25 日；LongCat-2.0 6 月 30 日
证据： A，Kimi 官方页面、LongCat 官方 GitHub 与博客

Kimi K2.7 Code

  • 1T 总参数、32B 激活参数、256K 上下文、MoonViT 视觉编码器，完整权重开放。
  • 官方称相较 K2.6 平均减少约 30% 思考 Token；API 缓存命中输入 $0.19/M、未命中 $0.95/M、输出 $4/M。
  • 专注长周期编码，始终启用 thinking；通用写作和对话官方仍建议使用 K2.6。

LongCat-2.0

  • 1.6T 总参数、约 48B 激活参数，训练覆盖 35T 以上 Token；完整训练和规模化部署均基于 AI ASIC 超级集群。
  • 使用 LongCat Sparse Attention，针对 1M 上下文训练；MIT 许可证，支持 GPU 与 NPU 部署。
  • 已对接 Claude Code、OpenClaw、Hermes 等智能体框架。

为什么重要

开放模型在“够用能力 + 可控成本 + 可部署性”上的组合越来越有吸引力。尤其是代码补全、仓库问答、批量静态分析等可回归测试的任务，未必需要最贵的闭源旗舰。

立即可做

  • 用同一代码任务集比较 GPT-5.6 Luna、Kimi K2.7 Code 和 LongCat-2.0 托管服务。
  • 重点测端到端 PR 通过率、测试是否真实运行、错误修改率和总成本，不只看 SWE-bench 宣传分数。

7. LeRobot v0.6.0 推动物理 AI 进入闭环工程

时间： 7 月 6 日
证据： A，Hugging Face 官方 GitHub Release；官方博客已索引

发生了什么

  • LeRobot v0.6.0 发布，覆盖 VLA、世界模型、奖励模型和强化学习，统一真实机器人与仿真评测路径。
  • 新版本引入或更新多项真实机器人与长周期操作基准，并优化数据加载；默认安装拆分为按需 extras，最低 PyTorch 升至 2.7。
  • 项目已支持低成本机械臂到人形机器人，并用统一数据格式管理视频、状态和动作数据。

为什么重要

物理 AI 的核心不只是更大的 VLA 模型，而是“采集失败样本 -> 评估 -> 奖励判断 -> 改进策略 -> 再部署”的闭环。LeRobot 正在把这一闭环标准化并降低实验门槛。

立即可做

  • 升级前检查 breaking changes，尤其是安装 extras、导入路径、PyTorch 2.7、训练配置字段和 RL API。
  • 机器人项目优先建设统一数据与评测管线，再引入更大的策略模型。

建议行动清单

今天完成

  1. 建立一个 20 题真实任务集，开始测试 GPT-5.6 三档模型的质量、成本和延迟。
  2. 用 ChatGPT Work 跑一个非敏感、可核验的周期任务，记录失败点和需要人工批准的步骤。
  3. 为现有 Agent 增加最小审计字段：模型、Prompt/Skill 版本、工具调用、审批、成本、工件。

本周完成

  1. 建立模型路由表：简单批处理、常规交互、复杂长任务分别绑定默认模型和升级条件。
  2. 将 Prompt 与 Skill 纳入版本控制，并为每次发布保存固定评测结果。
  3. 对开放编码模型做一次小规模替代测试，寻找可从旗舰模型迁移的低风险任务。

暂不追逐

  • 只靠单一厂商基准得出的“全面超越”结论。
  • 尚无清晰 API、权重、价格或可用性说明的传闻模型。
  • 没有权限边界、审计日志和人工审批机制的全自动生产 Agent。

未来 7 天观察清单

  • GPT-5.6 多智能体 API 的正式文档、配额与定价是否公开。
  • GPT-Live API 是否开放，以及全双工流式协议、工具调用和并发定价。
  • ChatGPT Work 在 Plus/Business 的实际 rollout，以及 Codex 桌面项目迁移体验。
  • Mistral Prompt/Skill 版本控制的导出、回滚、环境隔离和评测集集成能力。
  • Kimi K2.7 Code、LongCat-2.0 的第三方复测、吞吐和真实部署成本。
  • LeRobot v0.6.0 的 breaking changes、机器人兼容矩阵和新评测稳定性。
